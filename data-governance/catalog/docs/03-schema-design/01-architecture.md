## 1. 全体構成図

```
┌───────────────────────────────────────────────────────────────────┐
│ 収集対象（画面あり業務システム）                                    │
│   ・ソースコード（enum / 定数 / ORMマッピング 等）                 │
│   ・設計書（テーブル定義書 / コード値一覧 / 画面設計書）            │
│   ・画面定義（プルダウン等の選択肢定義）                            │
└───────────────────────────────────────────────────────────────────┘
                 │  収集・機械的抽出（定期実行）
                 ▼
┌───────────────────────────────────────────────────────────────────┐
│ Bronze層（RAW）                                                    │
│   メタ情報（出典・抽出日時・抽出バッチID）付きの生データテーブル    │
│   ・RAW_COLUMN_DEFINITION      列名定義の抽出結果                  │
│   ・RAW_CODE_VALUE_DEFINITION  区分値定義の抽出結果                │
└───────────────────────────────────────────────────────────────────┘
                 │  名寄せ・重複排除・競合検知
                 ▼
┌───────────────────────────────────────────────────────────────────┐
│ Silver層（STAGING）                                                 │
│   名寄せ中の中間テーブル（競合フラグ・要確認フラグ・集約元参照）    │
│   ・STG_COLUMN_CANDIDATE       列名対応の名寄せ候補                │
│   ・STG_CODE_VALUE_CANDIDATE   区分値対応の名寄せ候補              │
└───────────────────────────────────────────────────────────────────┘
                 │  レビュー・確定（自動昇格 or 人によるレビュー）
                 ▼
┌───────────────────────────────────────────────────────────────────┐
│ Gold層（MART）                                                      │
│   区分値マスタ・列定義マスタ（版管理あり。カタログとして公開）      │
│   ・DIM_COLUMN_MASTER          列定義マスタ（物理名⇔論理名）        │
│   ・DIM_CODE_VALUE_MASTER      区分値マスタ（コード値⇔表示ラベル）  │
└───────────────────────────────────────────────────────────────────┘
                 │  参照
                 ▼
        対象DBの利用者・他システム（カタログとして参照）
```

## 2. Snowflake上のDB／スキーマ構成

各層をスキーマとして分離し、権限（GRANT）もスキーマ単位で管理する。

```
DATABASE: DG_CATALOG
├── SCHEMA: BRONZE     … RAW_* テーブル一式（収集バッチのみ書き込み可）
├── SCHEMA: SILVER     … STG_* テーブル一式（名寄せ処理バッチのみ書き込み可）
├── SCHEMA: GOLD       … DIM_* テーブル一式（レビュー確定処理のみ書き込み可、
│                          利用者・他システムは参照のみ）
└── SCHEMA: META       … 収集バッチ管理・ソースシステム管理などの運用メタデータ
```

| スキーマ | 役割 | 書き込み主体 | 参照主体 |
|---|---|---|---|
| BRONZE | 抽出した生データの保持 | 収集・抽出バッチ | SILVER変換バッチ |
| SILVER | 名寄せ・競合検知 | 名寄せバッチ | レビュー担当者、GOLD昇格バッチ |
| GOLD | 確定済みカタログ | レビュー確定バッチ | 対象DB利用者、他システム、BIツール等 |
| META | 収集バッチ・ソースシステム管理 | 収集バッチ、運用担当者 | 全バッチ処理（実行制御・ソース管理用） |

## 3. トレーサビリティの担保方法

- Bronze層の各レコードは `RAW_ID` を主キーとして持ち、出典メタ情報を保持する
- Silver層の各レコードは、集約元となった `RAW_ID` の配列（Snowflakeの`ARRAY`型）を
  `SOURCE_RAW_IDS` として保持する
- Gold層の各レコードは、確定根拠となった `STG_ID` （さらに`SOURCE_RAW_IDS`経由で
  `RAW_ID`）への参照を保持する
- 上記の連鎖により、Gold層のある1レコード（例：特定テーブルのある区分値の
  表示ラベル）について「どのソースコード／設計書のどの記述が根拠か」を
  Bronze層まで機械的に遡って特定できる

## 4. 更新・自動反映のデータフロー

```
[収集バッチ]                 (定期実行、例: 週次)
   │ 新規抽出データを追加（既存Bronzeレコードは不変・追記のみ）
   ▼
[Bronze]
   │ 前回バッチとの差分を検出
   ▼
[名寄せバッチ]
   │ 正規化・突合・競合検知
   ▼
[Silver]
   │ 競合／要確認フラグなし → 自動昇格
   │ 競合／要確認フラグあり → レビュー待ちキューへ
   ▼
[Gold]（新バージョンとして追記。既存有効レコードは有効終了日を設定）
```

詳細な抽出ルール・名寄せルール・競合解決ルールは
[02-data-transformation/01-conversion-policy.md](../02-data-transformation/01-conversion-policy.md) を参照。
テーブルごとの列定義は [02-table-definitions.md](02-table-definitions.md) を参照。
