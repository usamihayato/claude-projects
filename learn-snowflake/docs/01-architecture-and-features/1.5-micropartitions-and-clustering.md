# マイクロパーティション（分野1.5: Snowflakeストレージ概念の説明）

情報源: https://docs.snowflake.com/ja/user-guide/tables-clustering-micropartitions

## マイクロパーティションとは

Snowflakeが採用している独自のデータ格納方式です。従来のデータベースのような「ユーザーが手動で定義する静的パーティション」ではなく、テーブルにデータが挿入/ロードされると、**Snowflakeが自動的かつ透過的に小さな単位へ分割**します。ユーザー側での定義・管理は一切不要です。

## 基本構造

- 1つのマイクロパーティションは**非圧縮で50MB〜500MB**のデータを含む
- 実際に圧縮されて保存されるため、ディスク上の実サイズはこれより小さくなる
- データは**挿入/ロードされた順序**に基づいて分割される（自然に時系列や取り込み順で区切られやすい）

## 列指向ストレージという特性

マイクロパーティション内部では、データは**列ごとに独立して保存・圧縮**されます。これにより、クエリが特定の列だけを必要とする場合、そのカラムのデータのみを効率的にスキャンでき、不要な列の読み込みを避けられます。

## データスキュー（偏り）の防止

マイクロパーティションは均一に小さいサイズに保たれ、値の範囲がパーティション間で重複することも許容されます。これにより、特定のパーティションだけが極端に大きくなる「データの偏り」を回避しやすい設計になっています。

## クラスタリングメタデータとプルーニング

ここが試験で特に狙われるポイントです。

1. **メタデータの自動記録**: データ挿入時、各マイクロパーティションについて「含まれる値の範囲」「個別値の数」などのメタデータが自動的に記録される
2. **プルーニング（枝刈り）**: クエリ実行時、Snowflakeはこのメタデータを見て「このクエリの条件に該当するデータが絶対に含まれていない」パーティションをスキャン対象から除外する
3. **効果**: 例えば1年分のデータから特定の1時間だけを検索するクエリであれば、理想的にはその時間帯に対応するごく一部のマイクロパーティションのみがスキャンされる

つまり、**マイクロパーティション自体がテーブルの物理構造**であり、**クラスタリング情報はそのメタデータ**、**プルーニングはそのメタデータを使った検索の最適化**という関係になります。

## クラスタリングの「深さ」

マイクロパーティション間で値の範囲がどれだけ重複しているかを示す指標です。

- 深さが**小さいほど**クラスタリングが良好（重複が少ない）
- 深さが小さいと、範囲を絞り込むクエリに対して非常に高速な応答が期待できる

## 監視用のシステム関数

| 関数 | 用途 |
|---|---|
| `SYSTEM$CLUSTERING_DEPTH` | クラスタリングの深さを数値で確認 |
| `SYSTEM$CLUSTERING_INFORMATION` | クラスタリング状態の詳細情報を確認 |

これらは、大量のDML実行後にテーブルの品質（クラスタリング状態）が劣化していないか、あるいは明示的にクラスタリングキーを指定した効果が出ているかを測定するために使います。

## 試験対策チェックリスト

- [ ] マイクロパーティションはSnowflakeが自動生成することを理解している（ユーザー定義ではない）
- [ ] マイクロパーティションのサイズ（非圧縮50〜500MB）を覚えている
- [ ] 列指向ストレージによってスキャン効率が上がる理由を説明できる
- [ ] クラスタリングメタデータとプルーニングの関係を説明できる
- [ ] クラスタリングの「深さ」の意味（小さいほど良好）を理解している
- [ ] `SYSTEM$CLUSTERING_DEPTH` / `SYSTEM$CLUSTERING_INFORMATION` の用途を知っている

## よく出る問題パターン

**Q. Snowflakeでパーティションはどのように作成されるか？**
→ A. ユーザーが明示的に定義するのではなく、データのロード/挿入順序に基づいてSnowflakeが自動的に作成する

**Q. マイクロパーティションのサイズはどの程度か？**
→ A. 非圧縮で50〜500MB

**Q. クエリのプルーニング効率を確認する方法は？**
→ A. クエリプロファイルで「スキャンされたパーティション数」と「パーティションの合計数」を比較する（分野4.1と関連）
