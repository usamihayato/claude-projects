# クラスタリングキー（分野4.2: クエリパフォーマンスの最適化）

情報源: https://docs.snowflake.com/ja/user-guide/tables-clustering-keys

前提知識: [マイクロパーティション](../01-architecture-and-features/1.5-micropartitions-and-clustering.md)（分野1.5）

## クラスタリングキーとは

「同じマイクロパーティション内に、特定の列の値が近いレコードを共存させるために、ユーザーが明示的に指定する列のサブセット」です。

マイクロパーティションは**Snowflakeが自動生成**するものですが、クラスタリングキーは**ユーザーが明示的に指定して、その自動分割のされ方に介入する**ための仕組みです。両者の関係を整理すると以下の通りです。

| 概念 | 誰が制御するか | 役割 |
|---|---|---|
| マイクロパーティション | Snowflakeが自動 | データの物理的な分割単位そのもの |
| クラスタリングキー | ユーザーが明示的に指定 | マイクロパーティション**内**のデータ配置を意図的に最適化する |

## クラスタリングを検討すべきテーブルの条件

以下の**すべて**を満たす場合に効果的とされています。

1. **規模**: 数TB規模の、多数のマイクロパーティションを持つ大規模テーブル
2. **クエリ特性**: 選択的なフィルター（WHERE）処理やソートを伴うクエリが多い
3. **アクセスパターン**: 多くのクエリが**同じ列**の恩恵を受ける（バラバラな列でフィルタしている場合は効果が薄い）

さらに、**頻繁に照会され、更新が少ない**テーブルほど費用対効果が高いとされています（更新が多いと再クラスタリングのコストが頻発するため）。

## クラスタリングキーの選定戦略（優先順位）

| 優先度 | 選定基準 |
|---|---|
| 第1優先 | SELECT述語（WHERE句）で最も頻繁に使われる列（例: 日付） |
| 第2優先 | JOIN述語で頻繁に使われる列 |

**カーディナリティ**（列に含まれる個別値の数）のバランスが重要です。

- 個別値が多すぎる → プルーニングは効くが、グループ化がしにくい
- 個別値が少なすぎる → グループ化はしやすいが、プルーニング効果が薄い

複数列を指定する場合は**最大3〜4列**を推奨。並び順は**低カーディナリティ→高カーディナリティ**の順に配置します（例: `国` → `都道府県` → `日付` のように、粗い粒度から細かい粒度へ）。

## 再クラスタリングの仕組み

テーブルへのINSERT/UPDATE/DELETEなどのDML操作が続くと、データの並び順が乱れ、クラスタリングの品質（=クラスタリングの深さ）が徐々に劣化します。

- **自動再クラスタリング**: Snowflakeがバックグラウンドで自動的に検知・実行。ユーザーはテーブル名を指定するだけで、手動でのメンテナンス操作は不要
- **処理内容**: クラスタリングキーに従って列データを再編成し、関連レコードを同じマイクロパーティションへ再配置。結果として新しいマイクロパーティションが生成される

### コストへの影響（試験で狙われやすいポイント）

| コスト種別 | 内容 |
|---|---|
| クレジット消費 | 再クラスタリング処理自体がDML相当のコンピュートを消費する |
| ストレージコスト増 | 再編成前の古いマイクロパーティションも、Time Travel・Fail-safe期間中は保持され続けるため、その分ストレージが増える |

## 検索最適化サービスとの違い（混同注意）

非常に混同しやすいので整理します。

| 項目 | クラスタリングキー | 検索最適化サービス |
|---|---|---|
| データの物理的な再配置 | **する**（マイクロパーティションを再編成） | **しない**（メタデータレベルの最適化のみ） |
| 得意なクエリ | 範囲フィルター・ソートを伴う大規模スキャン | ポイントルックアップ、テキスト検索、半構造化データの等価検索 |
| 適用単位 | テーブル全体（列の組み合わせを1つ指定） | クエリのパターンに応じて自動的に対象列を判断 |

## 試験対策チェックリスト

- [ ] クラスタリングキーとマイクロパーティションの違い（自動 vs 明示指定）を説明できる

- [ ] クラスタリングキーの選定優先順位（SELECT述語 > JOIN述語）を理解している
- [ ] 複数列指定時の並び順（低カーディナリティ→高カーディナリティ）を覚えている

## よく出る問題パターン

**Q. クラスタリングキーに複数列を指定する場合、どの順序で並べるべきか？**
→ A. カーディナリティの低い列から高い列の順に指定する

**Q. クラスタリングキーを設定した後、再クラスタリングは誰が実行する必要があるか？**
→ A. ユーザーが手動実行する必要はなく、Snowflakeが自動的にバックグラウンドで実行する

**Q. 頻繁に更新されるテーブルにクラスタリングキーを設定するとどうなるか？**
→ A. 再クラスタリングが頻発し、クレジット消費とストレージコストが増加するため、費用対効果が悪化しやすい

**Q. 大規模テーブルで特定の日付範囲のフィルターが遅い。クラスタリングキーとして最も優先すべき列は？**
→ A. WHERE句（SELECT述語）で最も頻繁に使われている列 — 多くの場合、この設問では日付列が正解になる
